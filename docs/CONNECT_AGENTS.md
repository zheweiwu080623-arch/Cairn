# 把 Cairn 接到"办公 AI"上（Qoder / 千问办公）

> ⚠️ **状态：实验性 · 已降级 · 不计入 9/28 发布范围**（2026-09-24 决定）
> 能力都在、随时能用，但**不算正式功能**：没在 Qoder 里实机验证过，千问办公本身也还没开放。
> 不用它，Cairn 一切照旧；想用就照下面做，出问题不影响其它任何功能。

> 2026-09-24 写的。背景：上海交大和阿里合作，给师生免费开了两款 AI 产品 ——
> **Qoder**（编程智能体，3000 credits/月）和 **千问办公**（办公 Agent，2000 credits/月）。
> 这份文档说清 Cairn 跟它们各自怎么配合、以及**边界在哪**。

## 一句话：不是谁替谁，而是各干各擅长的

| | 它们擅长的 | Cairn 擅长的 |
| --- | --- | --- |
| Qoder | 写代码、跑命令、读整个仓库、按目标持续干活 | 知道**今天该干什么**：日程、任务、DDL 倒计时、什么最要紧 |
| 千问办公 | 读文件、提炼信息、汇总表格、出文档/PPT 大纲 | 把散落的信息**收进来并排好序**，并把"要动手的"整理成文件 |

所以做法是：**Cairn 当数据源 / 工具，它们当执行者**。

## 一、Qoder：走 MCP（推荐）

Qoder 的 CLI 与桌面端支持 **MCP（Model Context Protocol）**，可以挂载外部工具。
Cairn 自带一个**只读**的 MCP 服务器：

```bash
# 先确认能用（不联网、不读写数据）
node bin/cairn-mcp.mjs --selftest
```

在 Qoder 的 MCP 配置里加上（路径换成你机器上的仓库位置）：

```json
{
  "mcpServers": {
    "cairn": {
      "command": "node",
      "args": ["C:\\Users\\<你>\\...\\codex-planner\\bin\\cairn-mcp.mjs"]
    }
  }
}
```

挂上之后，你在 Qoder 里可以直接问：

> 「用 cairn_today 看看我今天有什么，然后帮我把该准备的资料列个清单」
> 「用 cairn_tasks 找出 3 天内到期的，按紧急度排一下」
> 「用 cairn_course_search 找 'Lagrange remainder' 在哪份讲义里」

**提供的五个工具（全部只读）**：

| 工具 | 能问出什么 |
| --- | --- |
| `cairn_today` | 今天的日程 / 今天到期 / 已逾期 / 待看的提醒 |
| `cairn_tasks` | 任务清单（可筛），每条带倒计时与"下一次提醒" |
| `cairn_priority` | 按"未来规划"排出的重要信息，**带分数与理由** |
| `cairn_course_search` | 在课件里找一段话（哪份材料、第几段附近） |
| `cairn_packs` | 列/读 Cairn 已生成的学习产物（资料索引、每周巩固包…） |

**三条边界（刻意的）**：

1. **只读**：这些工具不会写你的数据库、不发通知、不推手机，**更不会替你提交作业**；
2. **走本机回环**：MCP 服务器只是去问 `http://127.0.0.1:3210` 的只读接口 —— 永远只有一个进程写库；
3. **用之前先把 Cairn 打开**：服务没起时工具会回一句人话（"先把 Cairn 打开"），而不是一串英文。

> 为什么不直接接 Qoder 的 Agent SDK？那是 npm / pip 包（`@qodercn-ai/qodercn-agent-sdk`），
> 与本项目"零第三方依赖、解压即用"的原则冲突。MCP 是标准协议，用 stdio + 内置能力就能实现，不引入任何依赖。

## 二、千问办公：走"授权一个文件夹"（它本来的用法）

千问办公的能力描述里写得很清楚：**按文件夹授权读取**，从文件里提炼待办、汇总表格。
所以最自然的配合是：**Cairn 把该给它看的东西，写成一个规整的目录**。

```bash
# 生成/刷新给办公 AI 看的目录（默认写 <数据目录>/for-agents）
curl -X POST http://127.0.0.1:3210/api/agent-export -H 'Content-Type: application/json' -d '{}'
```

目录里的东西（都是给人/给模型读的纯文本）：

| 文件 | 里面是什么 |
| --- | --- |
| `README-给办公AI看.md` | 先说清楚：这些文件是什么、什么时候生成的、**只读别改** |
| `今日.md` | 日程 + 今天到期 + 逾期 + 待看提醒 |
| `任务与DDL.md` | 未完成任务，每条带倒计时与"下一次提醒" |
| `重要信息.md` | 按规划排序的条目 + 每条的理由 |
| `学习产物索引.md` | 已生成的资料索引 / 每周巩固包在哪、多大、什么时候生成的 |
| `manifest.json` | 机器可读：schema、生成时间、每份文件的字段说明 |

用法：把这个目录**授权给千问办公**（它只读授权范围内的文件），然后问它
「把这个文件夹里的待办整理成一张表」「把今日和目标对齐一下，排出优先顺序」。

> 注意：这个目录里**不含**你的凭据、不含课程原始文件、不含数据库 —— 只有 Cairn 已经算好的结论。
> 想更保险就把备份目录也指到别处（见 `docs/DEVELOPER_GUIDE.md` 里自动备份那节）。

## 三、还不做、以及为什么

| 想法 | 现在的结论 |
| --- | --- |
| 把 Qoder/千问办公当 Cairn 的**模型后端** | 不做。Cairn 的模型接入走"沿用本机 Codex 配置"那条路（`lib/codex-config.mjs`），要换成 Qoder 需要它开放 API Key 形态的接口；目前没有证据表明它给第三方应用提供这种入口 |
| 用 Qoder Agent SDK 嵌进 Cairn | 不做。它是 npm/pip 依赖，会破坏"解压即用、零第三方依赖"这条产品特性 |
| 让它们**替 Cairn 写库** | 不做。外部 agent 只读；所有写操作（加任务、改设置、生成文件）都在 Cairn 里由你本人点 |
| 千问办公现在就接 | **等它开放**：文章里写"预计本月底开放领取"。目录导出这套**现在就能用**，等它开放了直接授权目录即可 |
