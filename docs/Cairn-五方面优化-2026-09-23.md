# Cairn 五方面优化清单（2026-09-23）

> **说明**：本清单的判断已并入《GitHub 发布前完整计划》（工作区 `outputs\GitHub发布前完整计划_2026-09-23.md`）
> 的「序 · Cairn 的本质与五方面优化」与「本周计划」两节；这里保留为**原始记录**，不再单独维护。

> 来源：邮件任务（iPhone）。诉求：Cairn 的本质是「多源信息汇总 → 分析 → 再处理」平台，
> 1) 三段分开；2) 汇总更多信息；3) 分析更快更有效；4) 更多再处理手段解决现实问题；
> 5) 再处理手段的发布/运行/创建/载入更方便（核心卖点）；且尽可能轻量化。
>
> 基线（实测）：`server.mjs` 2164 行 / 108 KB；`lib/` 65 文件；`modules/` 8 个模块；
> `contracts/` 9 张 schema；`data/` 310 MB；`public/` 84 MB；`tests/` 59 个测试文件。

## 0. 结论先行

- 最值钱的两件事：把**「再处理手段」升格为一等公民**（`module.kind = processor`），
  以及**三段各用一张契约串起来**（source-item / signal / action）。
- 轻量化最大的两块肉：`public/` 里两个 mp4 占 77 MB；`data/` 里多份整库备份各占 14 MB。
- 次之：`server.mjs` 单文件 2164 行，是「越做越重」的主要来源。

## 1. 把三段分开（汇总 / 分析 / 再处理）

**现状**：连接器（`lib/connectors/*`）→ 相关度/优先级 + LLM（`relevance` / `priority` /
`semantic` / `llm`）→ 任务、通知、摘要、推送、归档（server 里的 `xxxTick()`、`digest.mjs`、
`course-sync.mjs`、`autopush.mjs`、`mobile.mjs`）。功能都在，但**边界是模糊的**。

**可优化层**：

1. **契约层**：新增 `contracts/source-item.v1`（原始条目 + 出处 + 抓取时间 + 可信级）、
   `signal.v1`（分析产物：分数、理由、证据、置信度、投递三档）、`action.v1`（再处理产物：
   邮件/文件/任务/日程/外部调用 + 结果回流），各配 fixtures，沿用现在的 `contracts/` 习惯。
2. **职责层**：连接器只做「拉取 → 标准化 → 落 `connector_data`」；分析只做「读条目 → 产 signal」
   且保持**纯函数无 I/O**；再处理只做「读 signal → 产 action → 写回 `notifications`/`tasks` + 外部副作用」。
3. **幂等层**：每段用 `(source, external_id, content_hash)` 做幂等键，**任一段都能单独重跑**，
   不必整链重放。
4. **拆分对象（现状反例）**：`lib/course-sync.mjs` 41.5 KB 同时干「抓 Canvas / 命名 / 归档桌面 /
   推办公本 / 发邮件」五件事；`lib/digest.mjs` 兼挑选与渲染；`server.mjs` 的定时器与业务耦合。

**收益**：换任一段实现不影响另两段；可分别限流、计费、测试。

## 2. 汇总更多信息

1. **配置即接入（优先）**：`lib/connectors/` 里的 `jsonapi` / `rss` / `ical` / `localfile` / `samples`
   已是通用型 —— 让「加一个源 = 填一段 `connector_config`」，只有 OAuth/加密类才写代码。
2. **连接器目录化**：`module.v1` 已有 `kind: connector`，第三方源做成 `modules/<id>/`
   （manifest + 抓取脚本），不碰主程序。
3. **增量与游标**：每源 cursor 存 `sync_state`，支持 `since` 与 `full` 两种模式；
   用 `external_id` + 内容 hash 去重（`dismissed_notifications` 已有「防复活」机制可复用）。
4. **调度与韧性**：每源独立 interval、安静时段（`lib/peak.mjs` 已有）、并发上限、
   失败隔离与退避（`lib/connector-errors.mjs` 已有）。
5. **值得加的下游源**（按能解现实问题排序）：教务/选课公告、图书馆借阅与到期、
   GitHub 关注项目的 release/issue、Zotero/arXiv 订阅细化、快递与账单、天气与通勤；
   微信/公众号这类无开放接口的，走「文件导出 → 本地源」而不是爬。
6. **治理**：给源标 trust 等级与抓取预算，否则「信息更多」会变成「噪音更多」。

## 3. 分析更快、更有效

1. **两级漏斗**：规则/关键词 + 向量粗排（`lib/semantic.mjs`）先砍到 top-N → 再 LLM 精评
   （`lib/llm.mjs`）；按内容 hash 缓存裁决，重复条目零成本。
2. **增量分析**：只分析新增/变更条目；把 score + 理由 + 证据写进 `connector_data`
   → 页面重渲染不必再分析。
3. **可解释与回流**：每条给 reasons / evidence / 置信度；界面「不相关」一键回写为
   `lib/relevance.mjs` 的规则，并用 `tests/relevance.test.mjs` 做回归，形成学习闭环。
4. **成本与时延**：LLM 调用批处理、嵌入缓存复用、避免每次请求读整库/整份 JSON。
5. **可量化**：每源「命中率 / 误报率 / 延迟」三个指标落库，周报里给出；现在只有「感觉更准」。

## 4. 更多再处理手段

1. **先固定形态**：`input = signal` → 决策（阈值/规则）→ `action`（邮件/文件/任务/日程/外部调用）
   → 结果回流 → 可回放（同输入同输出）。
2. **先做 8 个高频手段**：① 提炼成一封摘要邮件；② 日/周聚合报告；③ 生成文档（Word/PDF/LaTeX）；
④ 生成并运行脚本；⑤ 投递到设备（→ X5 书架）；⑥ 建任务/日程/提醒；
   ⑦ 归档与改名（课程资料那条链）；⑧ 触发外部 API（Bark/日历/网盘）。
3. **可组合**：手段能串成 pipeline，例：论文 → 结构化摘要 → 阅读清单 → 投 X5。
4. **安全**：每个手段声明 `permissions` 与 `data.reads/writes/tables`（`module.v1` 已支持），
   执行前可 `dry-run`，执行后留审计日志。

## 5. 手段的发布 / 运行 / 创建 / 载入（核心卖点）

**现状**：`modules/<id>/`（`module.json` + `view.js`）已成立，`lib/modules.mjs` 负责发现与校验，
`contracts/module.v1.schema.json` 定义格式，`docs/WRITING_A_MODULE.md` 教怎么写 → 「加功能 = 加目录」已成立。

**缺的三块**：

1. **`kind: processor`**（再处理手段）—— 现在只有 `view / connector / job / gadget`。
   补上后约定 `entry.run` 导出 `run(input, ctx) → actions[]`。
2. **入口**：`cairn mod new|test|run|install|list` + `POST /api/modules/:id/run`（默认 dry-run）。
   创建、运行、载入各一条命令。
3. **发布形态**：目录 → 打包（zip/tar）+ schema 校验 + **权限清单展示** + 来源（本地/git/URL）
   + 版本与回滚；卸载 = 删目录、数据保留。
4. **运行隔离**：独立进程 + 声明能力（表/网络/文件）+ 超时重试 + 日志，失败不拖垮主服务。
5. **与 agent 打通**：邮件派单（外部邮件桥）→ 选手段 → 执行 → 回信，这条通道现成，正好当发布后的分发入口。

## 6. 轻量化（按收益排序）

1. `public/` 84 MB：两个 mp4 就占 77 MB（`seq03.mp4` 58 MB、`wolf-duo.mp4` 19 MB）
   → 移出仓库、按需加载或转 webp + 懒加载。
2. `data/` 310 MB：整库备份每份 14 MB 且份数多，`-wal` 也有 14 MB
   → checkpoint + 只留最近 2–3 份 + 定期 `VACUUM`。
3. `server.mjs` 2164 行：拆到 `lib/routes/*`（已有先例），只留启动与接线。
4. 常驻进程：node + python + 两个托盘 = 4 个；看守合一（托盘与邮件桥由同一套看护脚本管理）
   这条继续走，把 Cairn 的看守也并进去。
5. 轮询：邮件桥每 15 秒登一次 IMAP，可拉长到 30–60 秒或改 IDLE；Cairn 的 tick 同理按需。
6. 依赖：继续保持零依赖（无 `node_modules`）+ SQLite 单文件 + JSON 契约；
   新功能优先做成模块目录，不进主程序。
7. 冷启动与内存：确保运行时是 SQL 查询而不是读整份 state JSON；视图按需 `dynamic import` + 懒渲染。
8. 加一个 perf 回归门槛（启动时间 / 内存 / 首屏 / 分析延迟）进 CI，防止越做越重。

## 7. 推进顺序

- **P0**：三张契约（source-item / signal / action）+ `kind: processor` + `cairn mod` CLI 骨架。
- **P1**：连接器配置化与增量游标（第 2 点）+ 两级分析漏斗（第 3 点）。
- **P2**：`public/`、`data/` 瘦身 + `server.mjs` 拆分（轻量化）。
- **P3**：手段 pipeline + 权限/审计 + 打包发布（第 4、5 点完整化）。
