# 数据源配置教程（从零开始，一步一步）

> 这份教程假设你**第一次打开这个应用**，也**不懂什么是 API / Token / IMAP**。
> 每一节都按「要准备什么 → 去哪拿 → 怎么填 → 出错怎么办」的顺序写。
> 现在一共可以接 **9 种数据源**，其中 **4 种不需要任何账号**（RSS / 日历订阅 / JSON 接口 / 本地文件）。

---

## 0. 先记住这三件事，能省掉一半的困惑

### ① 配置永远在「数据源」这一页

打开应用 → 左侧（或右上角菜单）进 **「数据源」** → 你会看到一排卡片，每张卡片是一种数据源。
**卡片上的输入框 = 这个数据源需要你提供的全部信息**，带 `*` 的是必填。

### ② 三个按钮的意思完全不同（这是最容易搞混的地方）

| 按钮 | 干什么 | 什么时候用 |
| --- | --- | --- |
| **示例演示** | 不用填任何东西，塞几条**假的**数据给你看长相 | 第一次想看看"接进来长什么样" |
| **导入 / 同步** | **真的去那个地方把数据抓回来**，放在页面下方的「已导入数据」里 | 填完字段之后 |
| **推送到日程/任务** | 把抓回来的条目**真正变成你的日程 / 任务 / 通知** | 确认条目没问题之后 |

> **关键**：只点「导入」不点「推送」，数据只是**停在数据源页**，不会进你的日程。
> 你可以先导入、看一眼、确认没问题，再推送 —— 这是故意设计成两步的。

### ③ 想先试一下，用「连接向导」或「示例演示」

「数据源」页上还有一个 **🪄 连接向导**（三步：选数据源 → 填字段 → **测试连接**）。
它和上面的卡片是同一件事的两种界面：

- **测试连接**只试不存 —— 成功会告诉你"能看到几条"，失败会用人话告诉你是哪个字段的问题；
- 卡片上的「导入 / 同步」是**直接干**（会真的写进你的应用）。

> 建议顺序：**先用测试连接确认能通，再用卡片导入。**

## 1. 不需要账号的四种（建议从这些开始）

### 1.1 通用 RSS / Atom 订阅

**适合**：校园公告、学院/系通知、博客、新闻、GitHub 项目的更新、知乎/掘金等带 RSS 的站点。

| 字段 | 说明 |
| --- | --- |
| `RSS / Atom 网址 *` | 这个订阅的网址，通常以 `.xml` / `.rss` / `/feed` 结尾 |
| `短名字` | 只影响显示，比如填「学院公告」，条目标题会带上这个前缀 |
| `只看最近 N 天` | 默认 7。老站点条目多时建议改成 3，避免一次涌进来 |
| `每次最多收几条` | 默认 30 |
| `只要包含这些词` | 逗号分隔，**只要标题/正文里有任意一个词就收**。例：`选课, 讲座` |
| `排除包含这些词` | 例：`促销, 广告` |

**怎么找一个网站的 RSS**：在浏览器地址后面试 `/feed`、`/rss`、`/rss.xml`；很多网站页脚有 RSS 图标；
也可以搜「站点名 + RSS」。

**常见问题**

- 导入后**一条都没有** → 多半是「只看最近 N 天」太短（改成 30 再试），或者这个 feed 本身很久没更新。
- 提示**不是合法的 XML/JSON** → 你贴的可能是一个网页地址，不是 feed 地址。

### 1.2 通用日历订阅（ICS / iCal）

**适合**：Google 日历、Outlook 日历、学校的教务/校历、课程表 App 导出的 `.ics`。

| 字段 | 说明 |
| --- | --- |
| `日历 .ics 链接 *` | 以 `.ics` 结尾的订阅链接 |
| `短名字` | 例：`学校校历` |
| `往后导入多少天` | 默认 60 |
| `往前导入多少天` | 默认 7（想看到已经过去的几天就留着） |
| `每次最多收几条` | 默认 200 |

**Google 日历怎么拿链接**：日历设置 → 「日历的公开地址」→ 复制 **iCal 格式**那个链接
（形如 `https://calendar.google.com/calendar/ical/.../basic.ics`）。
**注意**：要先把该日历设为"公开"或"任何人可查看"，否则拿到的链接是空的。

**常见问题**

- 重复日程只出现一次 → 解析器只展开**简单重复**（每天 / 每周，含指定星期几、次数上限）。
  复杂的（比如"每月第三个周四"）会只取第一次并注明原因。
- 时间对不上 → 本应用**保留文件里写的墙上时间**（不会偷偷按别的时区换算）。

### 1.3 通用 JSON 接口（任意网站/系统的数据）

**适合**：学校教务、公司内部系统、自建服务、任何"能返回 JSON 的接口"。

只要两件事：**地址** + **字段映射**（映射留空会自动猜）。

| 字段 | 说明 |
| --- | --- |
| `接口地址 *` | 例：`https://api.example.com/items` |
| `短名字` | 例：`教务系统` |
| `请求方式` | 默认 GET；有些接口只接受 POST 就填 `POST` |
| `访问令牌` | 可留空。填了会作为 `Authorization: Bearer <你的令牌>` 发出去 |
| `额外请求头` | 可留空。例：`{"X-Api-Version":"2"}` |
| `POST 请求体` | 只有用 POST 时才填。例：`{"page":1}` |
| `取哪一段` | 可留空自动猜。例：`data.items` |
| `标题字段` / `截止/到期字段` / `开始时间字段` / `结束时间字段` | 可留空自动猜 |
| `原文链接字段` / `唯一 ID 字段` / `正文/备注字段` | 同上 |
| `当成什么` | `event` 日程 / `task` 任务 / `reminder` 提醒，默认 `task` |
| `每次最多收几条` | 默认 100 |

**"取哪一段"怎么写**（这是最容易卡住的地方）：看接口返回的 JSON 长什么样，然后写"从外往里"的路径。

| 接口返回的样子 | 该填什么 |
| --- | --- |
| `[{...},{...}]`（根就是数组） | 留空 |
| `{"items": [...]}` | 填 `items` |
| `{"data": {"list": [...]}}` | 填 `data.list` |
| `{"code":0,"data":{"records":[...]}}` | 填 `data.records` |
| 数组里还有一层 | 支持下标，例 `data.list.0.rows` |

**留空会怎样**：它会依次去 `data` / `items` / `results` / `list` / `records` / `rows` 里找数组，
再退化成"整个响应里只有一个数组字段就用它"。所以**很多接口可以全留空直接成功**。

**时间怎么认**：秒级时间戳、毫秒级时间戳、数字字符串、`2026-09-24T14:30:00Z`、
以及纯日期 `2026-09-24`（**按当天 23:59 截止**）。认不出来的**原样保留**，不会乱猜。

### 1.4 本地文件导入（CSV / JSON / ICS）

**适合**：你已经攒在 Excel / 记事本 / 别的 App 里的表格；旧应用导出的一堆数据。

| 字段 | 说明 |
| --- | --- |
| `文件完整路径 *` | 例：`C:\Users\<你的用户名>\Desktop\tasks.csv`（在文件管理器里右键 → 复制文件地址） |
| `格式` | 留空按扩展名判断（`csv` / `json` / `ics`） |
| `短名字` | 例：`旧应用迁移` |
| `当成什么` | `event` / `task` / `reminder`，默认 `task` |
| 五个映射字段 | 列名/字段名，**留空自动猜**（中英文表头都认） |
| `最多导入几条` | 默认 200 |

**CSV 怎么写**（最省事的写法）：

```csv
标题,截止时间,备注,链接
交掉周三的实验报告,2026-09-23,记得带打印稿,https://canvas.sjtu.edu.cn/courses/1
预习线性代数第五章,2026-09-22 20:00,,
```

**它认得的中文表头**：标题 / 名称 / 事项 / 课程名；截止时间 / 截止日期 / 到期时间 / DDL；
开始时间 / 结束时间；链接 / 网址 / URL；备注 / 说明 / 描述。

**小提示**

- 表格里有逗号要写在引号里（`"上课, 带电脑"`），程序会正确识别；
- 文件大于 5MB 会被拒绝（这是防止误选了一个大文件把应用卡住）；
- **只会读你指定的那一个文件**，不扫描文件夹、不改动原文件。

## 2. 需要账号的五种（按难度从易到难）

### 2.1 arXiv 论文订阅（不需要密钥，但要选词）

**适合**：追 AI / CS 方向最新论文。

| 字段 | 说明 |
| --- | --- |
| `关键词` | 逗号或空格分隔，**命中任意一个词就要**。例：`agent memory, tool use, autonomous planning` |
| `arXiv 分类` | 空格分隔。常用：`cs.AI` `cs.CL` `cs.LG` `cs.CV` `cs.SE`。留空则只按关键词 |
| `排除词` | 命中就丢弃。例：`survey, position paper` |
| `只看最近 N 天` | 默认 3 |
| `每轮最多收录` | 默认 12 |
| `本地缓存小时数` | 默认 6，避免被 arXiv 限流 |
| `取数路径` | 默认 `auto`。官方接口限流时会自动降级到 RSS / OpenAlex，一般不用改 |

**常见问题**

- 关键词太宽（比如只写 `AI`）→ 一次涌进来几十条，建议用两三个词限定。
- 有新论文但没出现 → 先确认「只看最近 N 天」；再点一次「导入 / 同步」。

### 2.2 Canvas LMS（课程、作业、课件）

**适合**：用 Canvas 交作业的学校（SJTU 等）。接上之后能导入：**作业（转任务）**、
**日历事件（转日程）**、**新课件 / 公告 / 页面 / 模块（转通知）**，还能把新课件自动下载并按
`FA26_课程号_Week几_文件名` 重命名。

| 字段 | 说明 |
| --- | --- |
| `Canvas 域名 *` | 形如 `https://school.instructure.com`。**只要域名**，不要带 `/courses/...` |
| `API 访问令牌 *` | 见下面怎么拿 |
| `课程文件/资源回溯天数` | 默认 30。第一次接建议先用 7，确认没问题再放大 |
| `排除课程` | 课程代码 / ID / 名称片段，逗号分隔。例：`POL3610J` |

**怎么拿 Token（一步一步）**

1. 浏览器登录你的 Canvas；
2. 左上角头像 → **账号（Account）** → **设置（Settings）**；
3. 往下找 **「+ 新建访问令牌」（New Access Token）**；
4. 用途随便写（比如 `planner`），**过期时间选长一点**（比如学期末），点生成；
5. **复制那一长串**（离开页面就再也看不到了），粘到 `API 访问令牌` 里。

**常见问题**

- `401` → Token 无效或过期，重新生成一个（注意粘贴时别带空格）。
- `403` → Token 有效但没权限，确认这个账号能看到你要导入的课程。
- `404` → 域名写错了（通常是多写了路径，或漏了 `https://`）。
- 想删掉某门课的干扰 → 在「排除课程」里填课程代码。

### 2.3 交大邮箱（Zimbra）

**适合**：SJTU `@sjtu.edu.cn` 邮箱。同步进来的邮件会进 **「通知」**，而且是**重点来源**（会置顶）。

| 字段 | 说明 |
| --- | --- |
| `IMAP 服务器 *` | 固定 `mail.sjtu.edu.cn` |
| `端口(SSL) *` | 固定 `993` |
| `邮箱账号 *` | 你的完整邮箱地址 |
| `密码 / 应用专用密码 *` | **不是网页登录密码**，见下 |
| `最近 N 天` | 默认 7 |
| `屏蔽的发件域名` | 逗号分隔。例：`instagram.com, redditmail.com` |

**密码怎么弄**：到交大邮箱网页版的「设置 / 安全」里开启 **IMAP/SMTP 服务**，
系统会给你一串**授权码 / 应用专用密码** —— 填这个，不要填网页登录密码。

**常见问题**

- `LOGIN failed` / `AUTHENTICATIONFAILED` → 十有八九填的是网页密码，改用授权码。
- `IMAP is disabled` → 去邮箱设置里把 IMAP 打开。

### 2.4 通用邮箱（Gmail / QQ / 163 / 任意 IMAP）

**适合**：除交大邮箱之外的任何邮箱。同步进来的邮件默认进 **「通知」**（可在导入后用信息筛选把它压下去）。

| 字段 | 说明 |
| --- | --- |
| `IMAP 服务器 *` | Gmail：`imap.gmail.com`；QQ：`imap.qq.com`；163：`imap.163.com` |
| `端口(SSL) *` | 基本都是 `993` |
| `邮箱账号 *` | 完整邮箱地址 |
| `密码 / 应用专用密码 *` | 见下 |
| `最近 N 天` | 默认 7 |
| `Gmail 排除的分类` | 默认 `social,promotions,forums`（Gmail 专属） |
| `屏蔽的发件域名` | 逗号分隔 |

**各家的"密码"怎么拿**

| 邮箱 | 要做的事 |
| --- | --- |
| Gmail | 先开两步验证 → 到「应用专用密码」生成一串 16 位密码（**不能用**你的 Google 登录密码） |
| QQ 邮箱 | 设置 → 账号 → 开启 IMAP/SMTP → 生成**授权码** |
| 163 邮箱 | 设置 → POP3/SMTP/IMAP → 开启 IMAP → 生成**授权码** |
| 学校/公司邮箱 | 找「客户端授权码 / 应用密码」，或问 IT |

### 2.5 飞书 / Lark（企业自建应用）

**适合**：能把飞书**日历**同步过来（需要企业自建应用的凭据）。

> ⚠️ 这一类门槛最高：需要你有权限在企业里创建自建应用。**如果只是为了看群消息，不建议走这条路**
> （群消息需要机器人入群，会打扰群里其他人）。

| 字段 | 说明 |
| --- | --- |
| `App ID *` | 形如 `cli_xxxxxxxx` |
| `App Secret *` | 应用密钥 |

**大致步骤**：飞书开放平台 → 创建**企业自建应用** → 拿 `App ID` / `App Secret` →
在「权限管理」里开日历相关权限 → 发布应用（可能需管理员审批）。

## 3. 报错对照表（看到这些提示，八成是这几个原因）

应用会把底层英文报错**翻译成人话**再给你。下面是完整对照：

| 你看到的提示 | 真正的原因 | 怎么办 |
| --- | --- | --- |
| 「令牌无效或已过期…」 | Token 过期 / 复制多了空格 | 重新生成 Token，粘贴时注意首尾 |
| 「令牌有效但没有权限」 | 账号看不到那些课程 | 换有权限的账号，或重新生成完整权限的 Token |
| 「地址不对：域名要形如…」 | 域名带了路径 / 少了 `https://` | 只留域名，加上 `https://` |
| 「证书校验失败」 | 学校自签名证书 / 网络中间拦截 | 先用浏览器确认能打开该域名 |
| 「邮箱拒绝登录…」 | 用了网页登录密码 | 改用**授权码 / 应用专用密码** |
| 「邮箱的 IMAP 服务没开…」 | 邮箱设置里没开 IMAP | 去邮箱设置开启，或在网页版里找"客户端授权" |
| 「连不上服务器：服务器地址或端口不对」 | 端口写成 143 / 服务器拼错 | IMAP 一般 `imap.xxx.com` + `993`（SSL） |
| 「域名解析不了…」 | 地址拼错 / 本机 DNS 有问题 | 检查拼写；浏览器能不能打开这个域名？ |
| 「连不上这个地址…」 | 网络不通或需要代理 | 先用浏览器打开该地址试试 |
| 「连接超时（等满 60 秒）」 | 数据源很慢 / 校园网限制 | 稍后重试；课程多时第一次会慢 |
| 「这个地址响应太慢，等超时了」 | 同上（fetch 被中断） | 同上 |
| 「连接被中途断开」 | 网络不稳或要走代理 | 换网络再试 |
| 「有必填项没填…」 | 带 `*` 的字段空着 | 补齐（通常是账号、密码、服务器地址） |
| 「还有必填项没填：接口地址」 | 连接向导里没填完 | 把列出来的字段填上再点测试 |

**成功时它怎么说**：

- 有数据：`连接成功，已经能看到 N 条数据（可以放心导入了）`
- 没数据：`连接成功（暂时没读到新数据，也会是正常的 —— 比如这几天没有新邮件）`

## 4. 安全与隐私（这些是设计时就定好的）

- **数据只在你本机**：抓回来的内容存在你自己电脑上的数据库里，没有任何云端上传。
- **凭据是加密存的**：Token / 密码 / App Secret 用 AES-256-GCM 加密后落盘；
  界面上回显的永远是掩码（`••••` 加末四位），**接口也不会把明文吐给任何脚本**。
- **留空 ≠ 清空**：密码框留空提交时，程序理解为"你没改"，继续用已存的真值 ——
  避免一次误点把 Canvas Token 清成空字符串。
- **只监听本机**：服务只绑定 `127.0.0.1`，同一局域网的其他设备访问不到。
- **仓库不含你的数据**：`data/` 目录整个不进 Git。

## 5. 常见问题（Q&A）

**Q：接了这么多源，会不会每天都被刷屏？**
不会。抓回来的东西会先经过**信息筛选**（按你的身份画像判断"这条跟我有关吗"），
分成三档：**推给你 / 待你确认 / 建议忽略**，并且**在高峰时段（工作日 9–12、14–18）不会主动打扰你**。
你还能反过来教它：同类的删 3 次它就记住，留 2 次它就优先。

**Q：可以同时接好几个源吗？**
可以，9 种都能同时接，每种还能接多个（比如两个 RSS、三个日历）。

**Q：导入失败了会不会把我原来的数据删了？**
不会。「导入」每次只替换**这个数据源自己抓回来的那批**（在数据源页里），
删除或修改你的任务 / 日程 / 通知都只能由你手动做。

**Q：怎么让它每天自动跑？**
「数据源」页有一块**每日自动同步**：勾上要同步的源、设一个时间、保存即可。
也可以点「立即同步」手动跑一次。自动同步抓回来的内容会先进 **「待批准」**，
你点头才进日程/任务（也可以在设置里开"自动批准"）。

**Q：我不想让别人看到我在用什么源。**
数据源配置存在你自己的库里，不进 Git。如果以后要发布应用给别人用，
发出去的是**代码**，不是你的 `data/` 目录。

**Q：想找一个网站的 RSS / 日历链接，怎么找？**
先用浏览器打开那个网站，看看页脚有没有 RSS 图标；日历类看「设置 → 共享 / 公开地址 → iCal 格式」。
实在找不到就把这个网站的名字发给我，我帮你看它有没有可用的接口。

---

## 6. 还想接第 10 种？

三种办法，从易到难：

1. **它其实有 RSS 或 .ics**：直接当第 1 节那两个用；
2. **它能返回 JSON**：用「通用 JSON 接口」+ 字段映射（第 1.3 节）；
3. **它什么都没有，只有一个网页**：那就得为新来源写一个"连接器"——
   一个文件（`lib/connectors/你的名字.mjs`）+ 注册一行，界面就会自动出现这个数据源。
   写法见 [WRITING_A_MODULE.md](WRITING_A_MODULE.md) 与 [HOW_IT_WORKS.md](HOW_IT_WORKS.md)。
