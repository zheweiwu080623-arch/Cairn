# 日报与晚报是怎么来的（给使用者的说明）

> 你可以在应用里直接读这一页：**「今日」页 → 日报 / 晚报卡片**，或打开 `/docs/DIGEST.md`。

---

## 它在做什么

一句话：**把"最值得先看的 3 条 + 建议"合成一段能一眼扫完的摘要。**

| | 回答的问题 | 长什么样 |
| --- | --- | --- |
| 重要信息（`lib/priority.mjs`） | 这条**对我多重要、有多急**？ | 一长串排好序的列表（适合有空时翻） |
| **日报 / 晚报**（`lib/digest.mjs`） | **我现在先看哪几条？** | 3 条 + 为什么 + 今天/明天的安排 + 建议 |

排序用的还是同一套引擎 —— 所以"哪条重要"在整个程序里只有一个定义，不会出现两张卡片说法不一样。

---

## 早报看今天，晚报看明天

| | 什么时候看 | 里面有什么 |
| --- | --- | --- |
| **🌅 早报** | 早上（16:00 之前打开就默认给你早报） | 最值得先看的 3 条（含"为什么"）→ **今天的安排** → 建议 |
| **🌙 晚报** | 傍晚之后 | 今天做完 / 没做完 → **明天的安排** → 最值得先看的 3 条 → 建议 |

两种都可以随时点开（卡片上有「早报 / 晚报」两个按钮），不用等到那个时间。

---

## 它从哪儿取数

全是你本机已有的数据，不需要额外填表：

1. **你的未来规划**（「今日」页那张卡里写的，一行一条）；
2. **里程碑 / 校历与考试 / 未来 14 天的任务与日程**；
3. **刚收进来的信息**（交大邮箱、Canvas、RSS 等）里排序靠前的几条。

每一条都会写明**为什么排在前面**（例如"明天内到期（+35）· 标题里就有'提交'（+12）"），
没有依据的时候就直说"未来几天没有明确要优先处理的信息"，不会硬凑。

这份榜单**宁缺毋滥**：过期的旧条目、以及"分档是低、又不是今明两天到期"的（例如验证码邮件）
都不会被列进来 —— 名单很短的时候，它说的是实话，而不是凑够三条。

---

## 建议有两档

- **规则版**：不联网、随时可用（就是打开卡片默认看到的那几条）；
- **agent 版**：点「让 agent 写建议」，用你自己配的模型，基于**同一份数据**写 2~3 条更具体的下一步。
  - **高峰时段（工作日 9–12 / 14–18）不会调用模型**；
  - 模型没配好或调用失败时，会自动回落到规则版，并用人话说明原因；
  - 怎么配模型：「数据源 → Agent 接入」（如果你是"别的模型跑在 Codex 壳子里"，选**「沿用本机 Codex 的模型配置」**）。

---

## 推到手机

卡片上的「推到手机」会把**当前这一份**（早报或晚报）推给手机（走已有的 Bark 通道）。

两条要记住的：

- **只有你点它才会发** —— 日报/晚报不会自己发，也不会改动你现有的提醒与定时邮件；
- 还没配手机推送的话，会直接告诉你"去「数据源 → 手机通道」填 Bark 密钥"，不会闷着不响。

---

## 邮件版：早报 / 晚报（各自开关，默认关）

如果你希望它**每天早上/晚上自己送到邮箱**（手机邮箱或办公本邮箱），在
「数据源 → 手机与办公本 → ③ 早报 / 晚报邮件」里开：

| | 默认时间 | 内容 |
| --- | --- | --- |
| 早报 | 07:00 | 日程清单 + **今天最值得先看的 3 条** + 建议 + 附件 `today-plan-日期.txt` / `planner-calendar.ics` |
| 晚报 | 21:00 | 日程清单 + **明天最值得先看的 3 条** + 今天完成情况 + 建议 + 附件 `evening-plan-日期.txt` |

两档的开关、时间、发送记录**完全独立**（关掉晚报不影响早报，反之亦然）；两个默认都是关的。
不想等定时，也可以点「立即发送一封」或「立即发一封晚报」。

---

## 它**不会**做的事

- 不会自己发推送 / 改通知 / 动任务（「推到手机」是你按的）；
- 不会删除或修改任何数据；
- 除了「让 agent 写建议」不联网。
