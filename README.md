## 这是什么

1. **它把你的信息收在一处**：Canvas 的作业与课件、邮箱里的通知、飞书里的日程、
   任意 RSS 订阅、任意日历订阅（`.ics`）、任意 JSON 接口、甚至你桌面上的一个表格文件 ——
   **全都进同一个池子**。
2. **它会筛**：不是所有东西都值得通知你。它按「你的身份」判断（你在上哪些课、关心什么、
   什么东西你反复忽略过），把不相关的挡掉，只把该出现的推到你面前。
3. **它本地跑**：数据存在你自己电脑上的一个文件里，凭据加密存放，**没有服务器、没有账号**。
   你可以把整个目录拷到另一台机器上接着用。
4. **它是个平台，不是一坨写死的功能**：整条链路被切成 **汇总 → 分析 → 再处理** 三段，
   每段各有版本化契约（`source-item.v1` / `signal.v1` / `action.v1`）；界面模块、再处理功能、
   能力都是「单个文件 + 一份声明」，**改任意一段不影响另外两段**；「能力搭建」页还能
   **拖能力 → 连线 → 试跑 → 存成新功能**（不用改内核）。想加自己的东西，先读
   [docs/WRITING_A_MODULE.md](docs/WRITING_A_MODULE.md) 与 [docs/WRITING_A_PROCESSOR.md](docs/WRITING_A_PROCESSOR.md)。

**它不是**：不是云笔记、不是又一个待办 App、也不是要你天天维护的工具。
它的目标是 —— **你一天只需要看它一眼。**

## 30 秒上手

> 只需要 **Node.js 22 或更高**。没有构建步骤，**不需要 `npm install`**（零第三方依赖）。

```bash
git clone <这个仓库地址> cairn
cd cairn
npm start
```

然后打开 **http://localhost:3210**。第一次进去，界面上会让你：

1. **选信息源**（可以随时跳过，之后在「数据源」页再填）；
2. **选 UI 风格**（内置多套主题，随时能换）；
3. 直接开始用。

> Windows 上还可以双击仓库里的启动脚本，让它变成托盘里的常驻小图标，
> 或者用 Edge 的 `--app` 模式开成一个独立窗口（看起来就像一个本地 App）。

### 已知限制（v1.0 · 如实写，不想让你误会）

**数据与材料**

- **数学字体 / 扫描版 PDF 抽不出正文**：实测某学期 64 份课程材料里有 **19 份**属于这类
  （LaTeX 特殊字体、PPT 子集字体、纯扫描件）。程序会**如实标注**「乱码·看原文」/「需 OCR」，
  不会假装读到了；接 OCR / 字体映射**排在发布之后**，不阻塞本版。
- **不做自动提交作业**：这是刻意的红线（提交永远由人来点）。程序只整理、提醒、生成材料。

**正在做、还没完的**

- **主程序仍是单文件（约 2000 行）**：正在按「汇总 + 分析 + 接口表留在主程序、其余搬出去」分批拆。
  已完成两批（服务器外壳：日志 / 静态 / 流式 / 浏览器；开机自启 / 手机通道），2198 → 1989 行，
  其余几批排在发布后。
- **课程辅助六项能力**：`①资料索引`、`③每周巩固包` 已可用；`②作业时间估算`、`⑤考前抱佛脚`、
  `练习反馈`（④⑥合并改版）在发布冲刺里陆续加上 —— 它们都只吃本地材料与任务数据，**只摘不编**
  （材料里没有的就说"没有"）。
- **「再处理功能」已实现的动作**：发通知 / 推手机 / 写文件；其它动作类型会**如实标成"未执行"**。

**还没做的**

- **OAuth2 类数据源**（要跳浏览器点「同意」的，比如 Google 日历）；
- **云数据库**（本机每天自动快照有，云端没有——想异地就把备份目录指到网盘同步文件夹）；
- **手机端仍是"把内容推到手机"**（Bark 短句 / `.ics` 订阅 / 今日文本），不是手机 App；
- **托盘与办公本（讯飞 X5）同步是 Windows 专属**（macOS / Linux 用浏览器直接开，功能自动降级）。
  开机自启两个平台都支持：Windows 放「启动」文件夹的快捷方式、macOS 写 LaunchAgent
  （`~/Library/LaunchAgents/com.cairn.planner.plist`，顺带兼职"挂了自动拉起"的看门狗）；
- **办公 AI 兼容层是实验性的、不属于本版发布范围**：`bin/cairn-mcp.mjs`（给支持 MCP 的工具用）
  与 `POST /api/agent-export`（导出可授权的只读目录）都在仓库里、随时能用，但**没在 Qoder 里实机验证过**，
  详见 `docs/CONNECT_AGENTS.md` 顶部的状态说明。

## 常见问题（FAQ）

**Q：它会把我的数据传到哪儿去吗？**
不传。全部在本机：**零账号、零第三方依赖**；`data/`（数据库、日志、密钥）被 `.gitignore` 排除、
永远不会进仓库；网络只连你自己配置的数据源（Canvas / 邮箱 / 飞书 / RSS…）与你自己配置的模型。
凭据在 `data/codex-planner.db` 里用 AES-256-GCM 加密，接口只回掩码。

**Q：需要先装什么？**
Node ≥ 22。或者直接下 Release 里的**交付包**——里面自带便携 Node 运行时，解压双击即可，不用装任何东西。

**Q：想接一个它还不支持的数据源？**
先看 `docs/CONNECT_SOURCES.md`。九种已支持：Course/Canvas、邮箱(IMAP)、交大邮箱、飞书、arXiv、
任意 RSS、任意 ICS 日历、任意 JSON 接口（自带字段映射）、本地 CSV/JSON/ICS 文件。
加新源 = 填配置或加一个目录，不用改主程序。

**Q：会帮我提交作业 / 写完作业吗？**
不会，这是刻意的边界（见上「已知限制」）。

**Q：我怎么确认这个仓库是干净的（没有夹带凭据）？**
仓库自带两个体检脚本，自己跑一遍就知道：

```bash
python scripts/public-check.py      # 扫工作区：会公开的内容里有没有凭据/个人信息
python scripts/history-check.py     # 扫 git 历史：.gitignore 只挡以后，挡不住以前
```

`scripts/local-commit.ps1`（双击「提交到本地仓库.cmd」用的那个）在提交前会**自动跑这两步**，
有真凭据就直接停下不提交。

**Q：怎么加一个功能 / 写一个自己的「再处理功能」？**
见 `docs/WRITING_A_MODULE.md`（模块）与 `docs/WRITING_A_PROCESSOR.md`（再处理功能）。
命令行只有六个动作：`cairn mod new / list / test / run / pack / install`。

**Q：为什么叫 Cairn？**
Cairn 是徒步者堆在路上的**石堆路标**——不替你走路，只让你知道"到哪儿了、往哪走"。
显示名可以在应用内改（写进 `data/brand.json`），不影响仓库里的代码名。

## 接一个数据源

界面上点「数据源」→ 选类型 → 填表 → 点「测试连接」。不需要改代码、不需要命令行。

> 📖 **每一步怎么填、凭据去哪拿、报错是什么意思**：看 **[数据源配置教程](docs/CONNECT_SOURCES.md)**
> （应用里也能直接读：数据源页 →「打开《数据源配置教程》」）。

| 类型 | 你要准备的东西 |
| --- | --- |
| 飞书 | App ID / App Secret |
| Canvas | 校区 + 一个 Token |
| 邮箱 | 服务器 + 账号 + 授权码 |
| arXiv | 关键词（可选分类） |
| **RSS / Atom** | 一个网址 |
| **ICS 日历订阅** | 一个 `.ics` 链接 |
| **JSON 接口** | 一个地址（+ 可选 Token）；字段名可以自己填，也会自动猜 |
| **本地文件** | 一个文件完整路径（`.csv` / `.json` / `.ics`） |

连接器可以声明 `notify: true`，抓回来的内容就会进「通知」——
**加新适配器不用改主程序**。

## 加一个功能（模块）

> **两个词，先说清**（全项目统一口径）：**功能 = 再处理运算的结果**（用户能看见、能用的那一件事）；
> **能力 = 再处理运算的能力**（可复用的原子动作，比如"读课程材料""推手机"）。
> **功能由能力拼出来** —— 把能力从"硬编码的注入"变成可登记、可复用的东西，是接下来的正事（见 `docs/DEVELOPER_GUIDE.md`）。

一个功能就是一个目录：

```
modules/我的功能/
  module.json    # 声明：我叫什么、装到哪个位置、我要读写什么、需要什么权限
  view.js        # 界面
  README.md      # 可选
```

放到 `modules/` 下面就会被自动发现，刷新页面就出现。
完整写法见 **[docs/WRITING_A_MODULE.md](docs/WRITING_A_MODULE.md)**。

仓库里已经带了 **14 个真实模块**作为例子。界面卡片类的（`kind: gadget`）：`getting-started`（从这里开始）、
`priority-feed`（重要信息）、`daily-brief`（日报 / 晚报）、`preclass-card`（上课前检查）—— 都挂「今日」页；
`ddl-card`（DDL 提醒）挂「任务」页；`connect-wizard`（连接向导）、`filter-profile`（信息筛选）、
`digest-preview`（每日摘要预览）、`agent-connect`（Agent 接入）挂「数据源」页；
`backup-card`（数据备份）挂「统计」页。**自己占一整页的**（`kind: view`）：`course-assist-view`（课程辅助）。
**再处理功能**（`kind: processor`）：`preclass-check`（上课前 Canvas 检查）、`course-assist`（课程辅助）、
`hello-processor`（示例，照着抄它）。

> **想知道它是怎么运作的**（不要求会写代码）：看
> **[docs/HOW_IT_WORKS.md](docs/HOW_IT_WORKS.md)** —— 一次点击背后走了哪四步、
> 每个文件夹干嘛、加一项功能要动哪里、数据存在哪、怎么验证。

> **想审这份代码 / 二次开发**：看 **[docs/DEVELOPER_GUIDE.md](docs/DEVELOPER_GUIDE.md)** ——
> 技术栈与选型理由、运行时组成、分层规矩、九个核心环节、**逐文件的代码地图**、
> 三条主流程走查、扩展指南、失败降级与历史教训。
> 想把信发到手机 / 办公本（可选的外部邮件桥）见 **[docs/MAIL_BRIDGE.md](docs/MAIL_BRIDGE.md)**。
> 想让 Cairn 帮你做一件具体的事（**再处理功能 / processor**）：看
> **[docs/WRITING_A_PROCESSOR.md](docs/WRITING_A_PROCESSOR.md)**，
> 命令行是 `node bin/cairn.mjs mod new|list|test|run|pack|install`。

## 隐私与安全

- **本地优先**：数据只在你自己的机器上（SQLite 一个文件 + 一个数据目录），**没有云端**；
- **凭据加密**：Token / 密码以 AES-256-GCM 加密后落盘，导出与日志里都会被打码；
- **默认不联网**：只有你主动配的数据源、以及你开启的同步任务会往外连；
- **仓库里不含任何真实数据**：`data/` 与凭据文件都在 `.gitignore` 里；
- 发布前跑过一遍「隐私体检」，公开仓库里没有任何个人信息。

> 仍然要说清楚：这是**作者自己每天在用**的工具，安全设计是按「个人自用」的标准做的。
> 上面那些凭据都放在你自己的机器上，请像对待浏览器保存的密码一样对待它们。

## 三分钟演示（讲给别人听）

对着这个顺序讲，三分钟能讲完，而且每一条都能当场点开看：

1. **0:00–0:30 一句定义**
   「它把我所有要看的入口收成一个，然后帮我筛掉不该看的。」
2. **0:30–1:10 打开「今日」**
   今天要交什么、今天上什么课、哪些通知值得看 —— 一屏之内。顺手指一下「为什么这条没出现」
   （它不是按标签过滤，是按「你是谁」判断的）。
3. **1:10–1:50 打开「数据源」**
   当场加一个 **RSS 网址**，点「测试连接」，几秒后条目就进来了。
   **这一步是全场最有说服力的**：不用写代码、不用账号。
4. **1:50–2:30 打开「模块」**
   指着 6 个模块说：「这些不是写死在程序里的，是目录；别人写的功能放进来就能用。」
   然后打开 `docs/WRITING_A_MODULE.md` 给他们看这份「怎么写」。
5. **2:30–3:00 打开「任务」或「日历」**
   讲**本地优先**：数据在你电脑上、凭据加密、没有服务器。收尾一句：
   「所以它不像一个 App，更像你自己的一个私人助理。」

> 演示前准备：把演示用的数据源先连好一个（演示时再加第二个），
> 并确认**没有真实个人信息**出现在屏幕上（需要的场合可以用仓库里的示例数据）。

> **Vol.1.9** · 更新记录见 [CHANGELOG.md](CHANGELOG.md)

一个**零依赖、开箱即跑**的独立**桌面应用**：日程 / 任务 / 养成 / 通知安排，并内置 **Codex 数据连接** 与
**飞书 / Canvas / 邮箱 数据导入**。

只用 Node 内置能力实现（`node:http` + `node:sqlite` + `node:tls` + SSE），无需 `npm install`。
桌面窗口通过系统已安装的 Edge 以 `--app` 模式打开（独立窗口、无地址栏、像原生应用），
不依赖 Electron、不依赖外网安装。

## 应用显示名

界面上的应用名不是写死的，按下面的优先级解析：

1. 环境变量 `PLANNER_APP_NAME`
2. `<数据目录>/brand.json` 里的 `{"app_name": "..."}`
3. 默认：`Cairn`

所以：**别人 clone 下来看到的是 Cairn**；作者本机的 `data/brand.json` 里写着自己的名字，
而 `data/` 已被 `.gitignore` 排除 —— 私人名字永远不会进仓库。

## 📱 手机与办公本同步（2026-09-13 新增）

在「数据源 / 连接 Codex」页有一张 **📱 手机与办公本** 卡片，四件事都能在界面上点：

1. **Bark 即时推送 → iPhone**：把 Bark App 里的密钥（形如 `https://api.day.app/xxxx/`）粘进来，点「发送测试推送」验证。之后**到点提醒、交大邮箱新邮件、Canvas 新动态**都会推到手机（来源可改，默认 `email_sjtu,canvas`；5 分钟内最多 5 条防刷屏）。
2. **日历 → iPhone 日历（两种方式）**：
   - **iCloud 直推（推荐，不需要同 Wi-Fi）**：填 Apple ID + **App 专用密码**（`appleid.apple.com` 生成）→「测试连接」→「立即同步到 iCloud」。Planner 用零依赖 CalDAV 客户端（`lib/caldav.mjs`）自动发现账号、按需新建名为 `Planner` 的日历、逐条 PUT 事件（每条带 `VTIMEZONE`），并按内容指纹做增量（实测第二次同步 0 次上传；改动 1 条只推 1 条；来源删除会同步 DELETE）。可设每天自动同步一次。
   - **局域网订阅（无需任何账号）**：卡片里给出 `webcal://<局域网IP>:3211/cal/<密钥>.ics`，手机连同一 Wi-Fi 打开说明页点「订阅日历」即可。主应用仍只监听 `127.0.0.1`，**3211 是只读独立小服务**，只暴露日历 `.ics`、今日安排 `.txt` 与说明页。
   两种方式共用同一份日历内容：课表按周次展开、假期自动跳过、单双周正确、DDL 与里程碑在内（当前 244 条事件）。
3. **每日摘要邮件 → 手机邮箱 / 办公本邮箱**：每天定时（默认 07:00，电脑开着才发）发「今日 + 明日安排 + 逾期任务」，附件 `today-plan-日期.txt`（办公本进书架）与 `planner-calendar.ics`（导入日历）。发信复用「数据源」里已配好的交大邮箱 / Gmail。
4. **办公本（讯飞 X5）中转**：`data/mobile/` 或你指定的网盘同步目录里会生成上面两个文件，用**数据线直接拷进书架**，或让 X5 从**百度网盘 / OneDrive** 下载。

相关接口：`GET/POST /api/mobile`、`POST /api/mobile/bark/test`、`POST /api/mobile/digest/send`、`POST /api/mobile/calendar/reset`、`POST /api/mobile/icloud/test`、`POST /api/mobile/icloud/sync`、`GET /api/mobile/calendar.ics`、`GET /api/mobile/today.txt`、`POST /api/mobile/files`、`POST /api/mobile/open-folder`；手机侧只读端点为 `GET /cal/<token>.ics` / `.txt`。
完整操作步骤（含防火墙、校园网隔离、办公本三条路线）见工作区里的《手机与办公本同步_操作指南》。

## 📥 课程资料自动同步（2026-09-15 新增）

在「数据源 / 连接 Codex」页有一张 **📥 课程资料自动同步** 卡片，把 Canvas 上的新课件真正送到你手里：

| 场景 | Planner 自动做什么 |
| --- | --- |
| Canvas 巡检发现**新动态**（作业 / 页面 / 大纲 / 通知） | 照旧写进「通知」并推 Bark |
| Canvas 巡检发现**新文件** | ① 下载到 `桌面\FA26课程资料\<课程>\`；② **不再发 Bark** |
| 下载时**办公本（讯飞 X5）连着** | 把课程资料里的 **PDF** 自动推进设备「书架」（`.ipynb / .py / .m / .zip / .xlsx / .docx` 等代码/文档不同步） |
| 下载时**没检测到办公本** | 交给**本机的邮件桥**发一封邮件（列出新材料 + 在电脑上的位置，PDF 可作附件） |
| 之后才插上办公本 | 10 分钟内自动补推那些还没进设备的 PDF |

要点：

- **课程归类**：按 Canvas `course_code` 里的课程号匹配桌面上已有的 `<课程号> <课名>` 文件夹（如 `ENGR1010J 计算机导论`）；
  「Undergraduate Students」这类学院口径课进 `00 学院文件与课程表`；没见过的课程号会新建文件夹。
- **不重复、不刷屏**：同一个 Canvas 文件只记一次台账（`course_files` 表）；设备上已有的（哪怕设备给它改了书名）会识别并跳过；
  同一批材料只发一次邮件；下载失败自动重试（最多 5 次，每 10 分钟一轮）。
- **不卡提醒**：下载 + MTP 拷贝在后台跑，4 秒一次的提醒调度不受影响；跑完会把「📥 已下载到…／📖 已同步到办公本…」补进对应通知。
- 界面按钮：**保存 / 立即执行一次 / 检测办公本 / 测试邮件通道**，下方是最近材料的台账（状态徽标）与上次执行结果。

### 🧹 每日清理历史记录

同一张卡片底部可以设「保留 N 天（默认 **10 天**）+ 每天 04:00 自动清理」，删除对象可选：
**已触发的通知 / 数据源导入的历史条目 / 被删通知的标记 / 专注记录 /（可选）已完成任务**。
未来的提醒与未完成任务**不会被删**。

**相关接口**：`GET|POST /api/course-sync`、`POST /api/course-sync/run`、`POST /api/course-sync/device`、
`POST /api/course-sync/folder`、`POST /api/course-sync/mail-bridge-test`、`POST /api/history/purge`。

### 📛 统一命名规则（2026-09-16 定稿，Vol.1.7）

课程资料在**桌面与办公本上使用同一套文件名**：

```
FA26_<课程号>_Week<n>_<去掉课程号的原文件名>
例：FA26_ENGR1010J_Week1_lec_1.pdf            ←  lec_1.pdf（ENGR1010J 第 1 周）
    FA26_MATH1860J_Week1_all_lecture_slides.pdf ←  math186_all_lecture_slides.pdf
    FA26_STAT1000J_Week1_Syllabus.pdf          ←  Syllabus_26FA_STAT1000J.pdf
    FA26_学院文件_Placement Test Announcement 2026.pdf   ← 学院口径材料用「学院文件」当 tag，不加 Week
```

- `Week<n>`：`n` 是材料在 **Canvas 上所属的学期周**，第 1 周 = 学期开学那一周（本机 2026-09-14）；
  周次由入库时记下的 Canvas 日期（`course_files.file_date`）算出，老记录回退到入库时间，超过 14 周截断为 `Week14`。
- 学期代号 `FA26` = F + 季节（FA 秋 / SP 春 / SU 夏）+ 两位年份。
- 只删「课程号那一截」（含教授写法 `math186` 这种简写）与重复的 `FA26_` / `26FA` 标记，**其余原名原样保留**。
- 规则幂等：`cleanStem()` 会吃掉自己加过的 `Week<n>` 段，重复执行不会滚成 `..._Week1_Week1_...`。
- 以后 Canvas 新文件下载时就按这个规则落盘；已有文件用卡片上的 **统一命名（预览）/（执行）** 一次性对齐
  （预览会先给改动清单）。规则可重复执行，再跑是 0 改动。
- 办公本 MTP 设备不支持改名，所以「改名」= 按新名重新导入 + 删掉旧条目（自动点掉系统的确认框）；
  设备上同名但字节大小不符的会先删再重导，避免半个文件。
- 已同步（`synced`）的台账条目改名后**保持 synced**，不会再被当成“还没进办公本”重发一批 PDF 邮件；
  办公本插上后再点一次「统一命名（执行）」，它会把书架上的旧条目删掉、按新名字重新导入。
- **邮件桥发出去的附件也用这套名字**（Vol.1.8）：没连办公本时发的那封「Canvas 新课件」邮件，
  附件名与正文清单都取上面的标准名（原来用的是 Canvas 的原始文件名）。
- 重名撞车的文件不会被删，统一挪进 `FA26课程资料\_重名或重复（可删）\<课程>\`。
- 解压出来的代码目录（`.ipynb` 之类）与 `说明.md` 不参与改名。

**相关接口**：`POST /api/course-sync/rename`（`{dry_run:true}` 只预览）。

## 功能

- **今日**：今天的日程、到期/逾期任务、即将到来的提醒、任务完成度、Codex 连接状态。
- **日程（三级钻取）**：
  - **月历**：以月历样式组织每天的关键任务/日程/校历标记；左侧列出「第 x 周」，点击某周切到周历；
  - **周历（课表）**：以周循环课表的时间网格形式整理每周日常，按时间块展示课程；点击某天顶部「星期 x」切到每日；
  - **每日**：两种可切换模式——**任务栏**（列表整理当天任务与生活）与**纵向时间轴**（按时段整理全天安排）。
- **任务**：待办 / 进行中 / 已完成 筛选，优先级（紧急/高/中/低）、截止时间、标签、一键勾选完成。
- **通知**：设置触发时间与重复（一次性/每小时/每天/每周/每月），到点后在应用内弹出横幅，并尝试推送浏览器通知（可直接点“测试”验证）。
- **界面与主题**：顶部**横向导航**，今日/日程/任务/通知等排布为横向；默认采用 **Persona 5 风格（黑红撞色 / 斜切角 / 网点 / 粗体大标题）**。右上角 **「🎨 风格」** 可随时切换界面风格（**P5 黑红** / **Persona 3R 水蓝与镜子**），并预留了扩展更多主题的位置。
  - **主菜单=竖排无方块大菜单**：打开应用先进入「主菜单」，像 P 系列那样**竖排大菜单**（01 今日 / 02 日程 / 03 任务 / 04 养成 / 05 通知 / 06 统计 / 07 Codex / 08 数据源），点击某个**才进入该模块**；**取消所有方块**，改为大字号文字 + 斜切/描边、活跃项红色高亮条。
  - **主菜单=竖排细体菜单(无序号+居中高亮)**：竖排菜单已**去掉左侧红色序号列(01–08)**；**选中项高亮放到中间**——选中项后面是**居中红色横幅**、左侧一个 **❯** 箭头，类似 P5 战斗菜单(参考 TODAY/CALENDAR/…)。**字体更细更张扬**：细斜体 + 白描边/红色错影 + 倾斜(P5)；或细斜体 + 水蓝辉光(P3R)。
  - **主菜单正中心**：主菜单大词已**放到屏幕正中心**(水平+垂直居中)，隐藏页头，选中项红色横幅 + ❯ 居中显示，与参考图一致。
  - **主菜单交互=两次点击**：主菜单改为**单击选中(高亮)、再单击进入**该模块；回到主菜单后光标停留在上次模块，再次点击即可直接进入。
  - **Codex 与数据源整合**：主菜单里的「Codex」与「数据源」这两个功能重叠项已**合并为一个「数据源」入口**；进入后**同时展示 Codex 连接**(自动化/会话/清理历史)与**数据源导入**(飞书/Canvas/邮箱 + 每日自动同步 + 待批准)。
  - **导航=返回/唤出主菜单**：顶部**已移除横向导航标签**，只留一条极简命令条（⌂ 主菜单 / 风格 / 快速添加）。切换功能靠 **「⌂ 主菜单」按钮** 或 **ESC 唤出主菜单**——从主菜单进入某模块，点 ⌂ 或按 ESC 退回主菜单再进其它模块。
  - **头像 + 环形导览菜单**：左下角小人已**换回你的头像**(黑色猫耳立绘)、**去掉面具设计**；点击头像呼出 **P5 战斗式环形导览菜单**（中心=头像，四周一圈红色横幅选项：今日/日程/任务/养成/通知/统计/Codex/数据源），点击某一项即进入对应模块，点中心或 ESC 收起——用这一圈导览进一步精简导航。
  - **环形选项=不规则斜切(非方框)**：环形导览的每个选项改为**前小后大的不规则斜切/棱形横幅**（`clip-path` 多边形，非完整方框），并**不均匀地插在头像周围**——不同距离/角度/透视缩放，红色错位底衬随底部，类似 P5 指令(PERSONA/ORDER…)的斜带样式。

  - **小人为你的头像 + 动画不变**：小人基底已换回**你的头像照片**（黑猫耳立绘，`object-position: top` 显示头部），**白面具(红眼缝+红角刺)作为覆盖层**叠在照片面部上；**动画保持原样**——P5 全屏约 5 秒把面具缓缓戴上，P3R 露脸并朝自己头部射击+蓝碎片；角落小人、环形导览中心、全屏主角都用该头像+面具。

  - **UI 小人 + 切换动画**：左下角基于你的头像（黑色猫耳 / 手执白色雏菊 / 清冷系角色）生成 UI 小人，切换风格时播放对应人格面具动画——P5 黑红为**戴上面具**（红白面具常显 + “TAKE YOUR HEART!”）；P3R 水蓝为**召唤器爆头**（蓝光爆裂 + 蓝色光环 + “I AM THOU · 汝即吾”）。

  校历按「学期 / 假期 / 考试 / 补课 / 其他」分类，填标题 + 起止日期即可，单天可以只填开始日期），

## 快速开始

环境要求：Node.js ≥ 22（内置 `node:sqlite` / `node:tls`），Windows / macOS / Linux。

```bash
cd <项目目录>
npm run desktop        # 启动服务并打开桌面窗口（Edge --app）
```

Windows 也可直接双击 **`启动桌面应用.cmd`**。

**桌面快捷方式（脱离浏览器标签独立运行）**：安装/构建时已在桌面生成了 **`Codex Planner`** 快捷方式。双击它即会（无控制台窗口地）后台启动本应用，并弹出一个 **独立的 Edge `--app` 窗口**（无地址栏/无标签，像原生应用）打开界面；若服务已在运行则复用现有实例。

**自定义应用图标**：桌面快捷方式已换上**应用自绘图标**(`app.ico`，黑底 + 红 X 的 Codex X 风格，256×256)，不再是 Edge 图标。

> 说明：桌面快捷方式图标的自定义已完成；运行中的 **Edge `--app` 窗口在任务栏/Alt-Tab 仍显示 Edge 图标**(需 Electron 无边框才能完全自绘)，这是系统对 Edge 窗口的限制。

**自绘窗口外观（不使用浏览器外观）**：应用顶部自带**自绘窗口标题栏**——左侧应用标识与标题，右侧**自绘的最小化 / 最大化 / 关闭按钮**；这些按钮通过本地接口（`/api/window/*` + Win32）真实控制窗口：最小化/最大化/关闭。界面主体为全套自绘 P5/P3R 主题 UI（导航、卡片、月周日历、小人、特效均非浏览器默认样式）。

> 说明：由于离线环境无法安装 Electron/打包成原生无边框窗口，桌面形态采用「Edge `--app` 独立窗口 + 自绘标题栏 + 自建窗口控制」。若需要**彻底去掉系统/Edge 的标题栏**（真正的无边框窗口），需要改用 Electron（有网时可一键迁移），届时窗口边框、拖拽、最大化动画等将完全由应用自己绘制。

仅在浏览器中打开（不弹桌面窗口）：

```bash
npm start
```

启动后访问：**http://localhost:3210**

- 默认端口 `3210`，可用 `PORT` 修改（`PORT=4000 node server.mjs`）。
- `OPEN_BROWSER=0` 关闭启动时的自动打开；`DEBUG_NOTIFY=1` 调试通知调度。

## 课表 / 校历 导入

## 数据存储

- 应用自身数据存于 `data/codex-planner.db`（SQLite：任务、日程、通知、连接器配置与导入数据）。

## 技术说明

- 后端：Node 内置 HTTP + `node:sqlite` + `node:tls`，REST API，SSE（`/events`）推送实时通知。
- 前端：无构建步骤的原生 HTML/CSS/JS 单页应用。
- `RRULE` 解析：支持 `FREQ=DAILY|WEEKLY|MONTHLY|YEARLY`、`INTERVAL`、`COUNT`、`UNTIL`、`BYDAY`、`BYMONTH`、`BYMONTHDAY`、`BYHOUR`、`BYMINUTE`。
- 连接器：飞书（开放平台 API）、Canvas（REST API）、邮箱（自研轻量 IMAP over TLS 客户端）。

## 后台常驻模式（2026-09-13 新增，同日增强为「看门狗版」）

**启动**（两种方式，任选其一，效果一样：都是无窗口后台运行 + 托盘图标）：

- 双击桌面快捷方式 **`空庭Coterie的Planner`** → 桌面外壳 `shell/dist/PlannerShell.exe`（原生托盘 + 面板窗口）。
- 双击项目里的 **`启动后台.cmd`** → PowerShell 托盘 `tray.ps1`（纯脚本版，外壳坏了也能兜底）。

两者都会：先探测 `http://127.0.0.1:3210/api/health`，**服务没在跑就自己拉起来**，已在跑就复用现成实例。**两个同时启动也只会有一个托盘**（单实例：外壳在跑时脚本版自动退出）。

> 沙箱 / 离线环境下服务能起来但拉不到外部数据，**飞书·Canvas·邮箱要在你自己的桌面会话里运行才有网**。

**看门狗（2026-09-13 增强）**：托盘常驻时**每 20 秒探活一次**，连续 2 次没有响应就自动重启后台服务，并弹一条气泡告诉你“服务曾中断，已自动重启”。以前只在启动时看一眼，服务中途挂掉就一直挂着——现在会自己爬起来。

**托盘图标在哪**：任务栏右下角；如果被折叠了，点任务栏的 `⌃`（上箭头，就是你截图里那个位置）就能看到。

**右键托盘图标**：

| 菜单项 | 作用 |

| 打开面板 | 打开 `http://localhost:3210` |

### Canvas 三小时巡检

- 后台服务每 **3 小时**自动拉一次 Canvas（`canvas_watch.interval_hours`，默认 3）。
- **巡检范围（2026-09-14 扩充）**：不只作业与日历，还包括
  1. **课程文件**：顶层 + **逐层子文件夹**（课件通常放在嵌套目录里）；
  2. **页面 / 资源页**：含课程首页正文摘要；
  3. **页面里链出去的文件**：有些大纲是 `hidden` 文件，**只挂在页面上、不出现在 Files 列表**，这类必须靠页面链接才能发现；
  4. **教学大纲**：课程设置里的 `syllabus_body`；
  5. **模块资料**：模块条目里挂的文件/页面（文件接口 401 时模块仍可见）。
- **时间过滤**：只把**最近 N 天**有变动的文件/页面转成通知（`lookback_days`，默认 30，可在「数据源 → Canvas」里改）；更早的材料只在导入列表里，不推通知，避免刷屏。
- **发现新条目 → 写进「通知」 + 弹一条 Windows 系统通知**（标题是课程/文件/页面名，正文最多列 3 条）。
- 服务启动 90 秒后先查一次；之后按 3 小时间隔。
- 同一门课/同一个文件或作业不会重复提醒：文件按 `file-<课程>-<文件号>` 去重，页面按「页面号 + 更新时间」去重（**页面被改动会重新提醒一次**）。
- 每次巡检都会在 `data/server.log` 记一行「拉取完成 {课程/作业/事件/文件/页面/大纲/模块} 共 N 条，新增 M 条」——**如果长期是 0 条，先去日志看是 token/网络问题还是真的没有新内容**（界面卡片也会显示上次各类条目数）。
- 巡检开关、间隔、立即巡检都可以在应用内 **「数据源」→「🛰️ 后台常驻」卡片**操作。
- 相关接口：`GET /api/canvas-watch`（状态）、`POST /api/canvas-watch`（改开关/间隔）、`POST /api/canvas-watch/run`（立即执行）。
