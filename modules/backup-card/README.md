# 数据备份（backup-card）

挂在「统计」页的卡片（**不占今日页**：今日只放"当下要知道的事"）。对应审阅意见
「考虑本地数据与云数据库备份。可以有自动归档，自动保存，定期清理之类的功能。」

| 它能做什么 | 怎么做的 |
| --- | --- |
| 自动归档 / 自动保存 | 心跳里按间隔（默认每 24 小时）检查，**库里没变过就不重复备**；用 SQLite 的 `VACUUM INTO` 生成一致快照 |
| 定期清理 | 只保留最近 N 份（默认 7），更早的自动清掉 |
| 想离开这台机器 | 把备份目录指到**网盘同步文件夹**（OneDrive / 坚果云…）＝零账号、零密钥的异地副本 |
| 手动 | 「立即备份（演练）」只说会写到哪；「立即备份（真备）」才落盘 |

接口：`GET /api/backups` · `POST /api/backups`（改设置）· `POST /api/backups/run`（默认演练）。
纯逻辑在 `lib/backup.mjs`，接口在 `lib/backup-stack.mjs`，落盘在 `lib/store.mjs` 的 `backupTo()`。

## 出事时怎么恢复

1. 退出应用（托盘右键退出，等 5 秒）；
2. 把要用的快照复制进数据目录、改名成 `codex-planner.db` 覆盖原库，并清掉同目录的
   `codex-planner.db-wal` / `-shm`（旧库的残留）；
3. 启动应用，用「统计」页的条数对一眼。

两点要记住：

- 快照里**只有数据库**。凭据是加密存储的，密钥在同目录的 `.secret.key` ——
  换机器恢复要带上它，否则数据都在、只是凭据要重填一次；
- **密钥不建议跟快照一起放网盘**（一起上传等于把锁和钥匙放同一个包里）。
