# 课程辅助（course-assist-view）

`kind: view` —— **自己的一页**，和「今日 / 日程 / 通知 / 音乐」并列（导航里一个图标，主菜单里也有一格）。

为什么单独一页而不是塞进「今日」：课程辅助是"要坐下来用的东西"（选目录、生成、看产物、
逐项推进六件能力），和今日页那种"扫一眼就走"的卡片不是一类。今日页只放**当下要知道的事**，
这里放**要动手做的事**。

页面上的东西：

| 区域 | 说明 |
| --- | --- |
| 资料目录 | 直接贴路径或点「📂 选择文件夹…」（走 `/api/localdirs`，key=`course`），改完立刻生效 |
| 生成 | 「生成资料索引（演练）」= 只规划、告诉你将会写到哪；「生成（真写）」才落盘 |
| 已生成的文件 | 读 `<数据目录>/study/` 的清单（走 `GET /api/course`），可一键打开那个文件夹 |
| 六项能力 | 每项写清产物文件名与**当前做到哪儿**（① 已有，其余计划中）——不玩"全都支持" |

它自己**不读课件**：真正干活的在功能 `modules/course-assist/`（processor），
读写规则在 `lib/course-assist.mjs`（纯逻辑）与 `lib/course-stack.mjs`（写文件的闸门）。

## 就地设置：右上角「⚙ 功能设置」（2026-09-27）

`module.json` 里声明 `settings: true` ⇒ 主程序把这一页右上角那颗按钮画出来，点开右侧滑出抽屉
（**覆盖式**，不挤压页面）。抽屉里的内容由**这个模块自己**的 `settings(host, ctx)` 画 ——
主程序根本不认识"命名模板"这种东西。

抽屉里两项：

| 项 | 说明 |
| --- | --- |
| ① 课程资料放在哪 | 走 `/api/localdirs` 的 `course` 键（`📂 选择文件夹…` = 系统选择框）——和「本机目录」、页面顶端那个框**同一处**，改哪边都一样、都是立刻生效 |
| ② 文件怎么命名 | 模板 + 变量按钮（`{学期} {课程号} {课程名} {周次} {原名} {日期} {类型} {序号}`）+ **实时预览**（拿你自己台账里的材料算，服务端算，只算不写）|

值的存法：**功能自己的键** `fn_course_assist`（对应 `fn.course_assist.*`），读写都在
`lib/function-settings.mjs`；接口三个：`GET /api/fn-settings`、`POST /api/fn-settings`、
`POST /api/fn-settings/preview`（在 `lib/routes/function-settings.mjs`）。

默认模板就是**原来的规则本身**（`{学期}_{课程号}_Week{周次}_{原名}`）—— 抽模板不是为了改默认值，
所以默认值必须与老规则逐字相同，否则老装机升级后文件名会集体漂移一次（`tests/naming-template.test.mjs` 钉住了这一条）。

改名范围是**两档**：默认"只影响以后"；选"顺便把已有材料也改名"时，**先跑一次演练**把"要改几个"如实摆出来，
用户再点一下才真改（改名不可逆，不该藏在"保存"后面）。
